# Accord development rules

Read [docs/ACCORD.md](docs/ACCORD.md) for the agreed premise and current implementation status. User instructions take precedence. Upstream CONTRIBUTING.md remains useful for source conventions; it does not override Accord's product requirements.

- This is a true Wrath fork: preserve upstream functionality and UI unless a change is needed for Accord to work. Separate packaging is not permission to rename upstream commands, IPC contracts or UI. Preserve `/wrath`, `/scombo`, inherited `WrathCombo.*` IPC, `OnActionUsed`, and upstream DTR/window names. Earlier combined-plugin removal decisions are superseded, including removal of Wrath's auto-status icon. Wrath's auto indicator and Accord's variant entries coexist.
- Preserve upstream engine behaviour. No unsolicited refactoring, simplification, library extraction, broad renaming, formatting sweeps or architectural rewrites. Make only changes necessary for the requested feature.
- Architecture decision 2026-10-16: Accord becomes a separate plugin. The Wrath fork owns rotation functionality and granular settings; Accord owns intent/variant mappings and sets engine settings through a validated API. Engine code must not depend on Accord variants, setup data or prepared-job state. See docs/separation.md; the source split and local preview packages are implemented; native acceptance remains pending. Hotbar Bridge remains separate. Preserve the agreed static/live behaviour and explicit selected-class setup. Accord manages only the saved active-class selection; deselection retains existing settings and hotbars.
- Clear other actions follows the existing cleanup scope, including intended empty slots, while preserving game-shared bars and Bridge's actual shared-slot map. Apply this option to explicit setup and live updates, retaining protection checks and backups.
- Variant names and count are not fixed to M/B/J. Checkboxes and individually clickable system information entries share one global selection; A/M means variant enabled/disabled. Do not connect these controls to the inherited hands-free auto-rotation toggle.
- Accord ships its simplified UI; the fork's own configuration interface is a separate concern, not an Accord Advanced fallback. The previous combined-plugin UI removal requirement is superseded. Preserve necessary engine configuration initialization independently of UI. The explicit 2026-10-16 request restores the existing auto-rotation runner under Wrath's own toggle and configures per-rotation Auto-Mode for Accord-selected jobs. Accord must not turn on the master auto toggle. Active-class selection defaults to none, including legacy missing/null selections.
- Added automation requires a specific gap, source evidence, optional behaviour, ST/AoE review, manual-access assessment and focused validation. Disabled additions must preserve upstream behaviour. Do not claim a button is redundant until all its required functions are covered.
- Buttons express intent; automation carries out that intent. Integrate standalone functionality only into appropriate intent paths. Manual burst initiation followed through by ST/AoE is the reference model; variants may delegate initiation. Do not make every button do everything or add all healer support to damage paths indiscriminately.
- The agreed initial variants are Auto burst, Auto protection, Auto support and Auto class mechanics. Class mechanics covers systems such as DNC dances, AST cards and BRD songs; GNB has no additional class-mechanic variant effect. Assign each initiator a single owner. A manual initiator signals intent; subsequent handling remains on the appropriate automation button, reusing existing logic rather than forcing repeated visits to a chained burst selector. Preserve successful-initiation, resource, cooldown and target conditions; do not replace the rotation engine.
- Evaluate allied-action eligibility against the resolved recipient and execute on that same recipient. Retargeting must influence selection as well as execution; an enemy selection must not by itself suppress an eligible support action for the resolved ally. Follow the documented AST investigation case and preserve action-specific targeting requirements.
- Review existing settings and hotbars for alignment with this philosophy; they are a starting point, not frozen layouts. Review resource-holding settings first, without a general rewrite of reserves, burst alignment, HP thresholds or content restrictions. Earlier exploratory resource-spending suggestions are not approved changes.
- Keep baseline configuration, variant toggles and upstream migrations distinct. Feature-only switching must not reset detailed settings. Accord requests updates through the fork API; the fork owns validation, mutation, persistence and cache refresh. Never write another loaded plugin's settings file.
- Preserve upstream commit history, licence and dependency notices. Track the upstream revision and isolate local patches so merges remain reviewable. Compilation and tests are not proof of in-game correctness.
- Accord and the compatible fork must load together. The fork, which owns action hooks, must prevent conflicting loading with upstream Wrath. Accord and the engine need separate plugin/configuration stores and packaging. Accord uses `/accord`; the engine retains upstream `/wrath` and `/scombo`. Existing Wrath integrations keep their original endpoint names. The newly added persistent settings API remains separate. Fork naming/repository allocation is not yet chosen. Existing combined preview artifacts are not a separated release.
- This is an independent nested repository. Do not add it as copied source to the parent HotbarTools repository. Do not publish personal configurations, exports or live game data.
